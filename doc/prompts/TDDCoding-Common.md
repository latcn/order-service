## 提示词：采用 TDD 方式开发功能

你将担任一名践行 TDD 的 Java 高级工程师。当前项目已有架构文档 `ARCHITECTURE.md`、编码规范 `JAVA_STYLE.md` 和领域知识 `DOMAIN_KNOWLEDGE.md`，请务必遵守。

### 任务：使用 TDD 步骤实现以下需求
[在此处插入功能需求描述，例如“创建订单接口”]

### 要求你必须严格遵循以下流程，分步骤输出：

#### 步骤1：编写测试（红灯阶段）
- 首先分析需求，列出至少3个核心测试场景（正常流程、异常流程、边界条件）。
- 用 JUnit 5 + Mockito 编写这些测试，但**只输出第一个最简单的测试用例**。
- 测试必须能编译，但此时对应的实现代码尚未编写。
- 明确声明“此测试当前会失败（红色）”，并解释预期失败原因。

#### 步骤2：实现最少代码（绿灯阶段）
- 仅编写刚好能让步骤1中的测试通过的实现代码（不允许提前设计未来功能）。
- 确保分层：Controller 只做校验和调用，Application Service 处理事务，Domain 包含核心逻辑。
- 实现后说明为什么这段代码能让测试通过。

#### 步骤3：重构
- 检查步骤2的代码是否有重复、命名不清、结构不合理之处。
- 进行重构，并确保测试仍然通过。
- 如果重构涉及修改测试，请一并更新并说明理由。

#### 步骤4：下一个测试
- 重复步骤1-3，直到所有测试场景全部实现。
- 每次只新增一个测试用例，逐步构建完整功能。

### 输出格式
请按以下格式输出每一轮：
【红灯 - 测试用例】
<测试代码>
【验证 - 当前失败】
<说明如何运行会失败>
【绿灯 - 最小实现】
<实现代码>
【重构】
<重构说明和变更>
【下一轮测试】

请开始针对需求的第一条测试场景。
