## 提示词：按 TDD 开发并同时满足架构约束

作为 TDD 教练，你不仅要保证测试驱动，还要让最终代码通过 ArchUnit 测试（规则见下方）。在每一步实现后，自行检查是否违反架构。

### 架构检查项
- Controller 不依赖 Repository。
- Application Service 的 public 方法有 @Transactional。
- Domain 层不导入 Spring 或 JPA 注解。
- 测试代码本身也必须遵守命名规范。

### 请在每一轮“重构”步骤中明确回答以下问题：
1. 当前代码是否符合分层架构？如果不符合，如何修正？
2. 是否有方法违反了 Checkstyle 配置中的规则（如空 catch、星号 import）？
3. 如果有违反，请直接在该步骤修复，无需等到最后。

### 开始 TDD 流程
需求：实现“查询订单详情”接口，输入订单ID，返回订单详情及所有订单项。

请从第一个测试开始。
